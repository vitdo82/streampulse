# VHS E2E Testing for the StreamPulse TUI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add terminal E2E tests for the TUI using [charmbracelet/vhs](https://github.com/charmbracelet/vhs) — scripted keystroke tapes that run the real `bin/streampulse` binary in a PTY, produce PNG screenshots for human review, and can be replayed live (`vhs play`) for demos.

**Architecture:** A new `tests/e2e/` directory holds `.tape` scripts (one per scenario), committed PNG screenshots in `tests/e2e/screenshots/`, and a `README.md` documenting what each tape verifies. A `make e2e` target runs preflight checks (vhs installed, Kafka reachable, binary built) then executes all tapes headlessly. `make e2e-watch` replays a tape live. VHS has no assertion primitive in v0.11 — verification is by (a) committed screenshots, (b) `vhs play` live review, and (c) post-run checks that every PNG was produced and is non-trivial in size. **Zero impact on the current setup:** no build tags needed (VHS is external to `go test`), nothing in `internal/` changes, `make test` is untouched.

**Tech Stack:** `vhs` v0.11.0 via Homebrew (verified available), the existing `make build` binary, docker-compose Kafka at `localhost:9093` (existing dev cluster), Makefile targets.

## Context review (verified facts)

- `brew` exists; `charmbracelet/vhs` latest release is **v0.11.0**; binary not yet installed.
- The TUI (`internal/tui`) is a bubbletea app using `tea.WithAltScreen` — VHS drives it through a real PTY, so alt-screen switching works and screenshots capture the actual UI.
- The TUI runs against the live cluster with `bin/streampulse --brokers localhost:9093` (default flag) — docker Kafka must be up (`docker compose up -d`, already running).
- Tab/keys: `1`-`6` jump tabs (Overview, Topics, Consumers, Alerts, DLQ, Analytics); `/` search; `enter` opens DLQ inspect (DLQ tab) or topic tail (Topics tab); `a` runs analyze CLI on the Analytics tab; `q` quits (or closes open views first); `esc` closes views.
- Live cluster provides deterministic fixtures: topics `orders`(6p), `payments`(3p), `inventory`, `audit`, `orders.dlq`, `payments.dlq`; producer writes every 2s; group `orders-processor` is Stable.
- VHS tape commands used (conservative, verified subset): `Output`, `Set` (Shell, FontSize, Width, Height, Padding, PS1), `Type`, `Enter`, `Tab`, `Escape`, `Up`, `Down`, `Sleep`, `Screenshot`, `Ctrl+C`.

## Verification model (honest scope)

- **What VHS verifies:** the TUI boots, renders, and responds to the scripted key sequence — evidenced by committed PNGs and clean tape exits (`q`/`Ctrl+C`).
- **What VHS v0.11 does NOT do:** text assertions. Deterministic screen-content checks stay in the existing unit tests (`internal/tui/model_test.go`). If CI assertions are wanted later, the follow-up is golden-PNG diffing (`compare`/pixelmatch) with fixed font rendering — explicitly out of scope for this plan.
- **Timing discipline:** tapes use `Sleep` generously (first scrape lands within 2s of boot; tail/DLQ reads are < 1s against local Kafka). No tape asserts volatile numbers — only stable labels (`TOPICS`, `orders`, `payments.dlq`, `TAIL orders`, `analyze --window`).
- **Failure modes:** Kafka down → `make e2e` preflight fails with a clear message (no tape runs, no stale screenshots); vhs missing → same; a tape that times out or can't exit leaves a stale PNG → the `make e2e` post-run message lists the output dir for inspection.

## Out of scope

Golden-PNG CI assertions, VHS GIF/WebM output, cross-platform font pinning, taping the daemon+store-mode TUI, automating `vhs` inside `go test`.
